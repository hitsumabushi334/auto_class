# 録画・スクリーンショット有効化チェックボックスのロジック実装計画

## 現状整理
- `main.py` の `SlideCaptureApp` クラスには「画面録画」「スクリーンショット」それぞれのチェックボックスが存在し、状態は `self.recording_enabled` / `self.capturing_enabled` に保持されている。
- `start_tasks` メソッドではチェックボックスの状態に関わらず `prepare_save_folder()` 実行後にスクリーンショットを開始し、ウィンドウが選択されていれば録画を開始している。
- チェックボックスの選択状態を変更した際のハンドラ `on_toggle_recording` と `on_toggle_capturing` はログを記録するのみで未実装。

## 実装要件
1. 画面録画のチェックが外れている場合は録画処理を開始しない。
2. スクリーンショットのチェックが外れている場合はスクリーンショット処理を開始しない。
3. 両方ともチェックが外れている状態で「開始」ボタンを押した場合は警告メッセージを表示し、処理を開始しない。

## 実装ステップ
1. **チェックボックス状態の即時反映と開始ボタン制御**
   - `on_toggle_recording` / `on_toggle_capturing` で `self.recording_enabled` / `self.capturing_enabled` を更新済みのため、ここに開始ボタンの活性/非活性制御を追加する。
   - 具体的には、両方とも `False` のときに `self.start_button.config(state=tk.DISABLED)` とし、それ以外では `tk.NORMAL` に戻す。
   - 現在実行中の場合 (録画・キャプチャ中) に強制的に無効化しないよう、`self.is_recording` / `self.is_capturing_screenshot` を確認して UI 更新が矛盾しないようにする。

2. **開始処理前のガード追加**
   - `start_tasks` 冒頭で `self.recording_enabled` と `self.capturing_enabled` を確認し、両方とも `False` の場合は `messagebox.showwarning("処理を開始できません", "画面録画とスクリーンショットが両方オフになっています。少なくとも一方を有効にしてください。")` を表示し、早期 return する。
   - 上記警告ではログにも `logger.warning` を残す。

3. **個別処理の条件分岐**
   - `start_tasks` 内のスクリーンショット開始と録画開始を `if self.capturing_enabled:` / `if self.recording_enabled:` で包む。
   - 録画開始時には従来通りウィンドウハンドルが選択されているかをチェックする。チェック済みでない場合はログを出しつつ録画開始をスキップする。
   - いずれかをスキップした際にも UI ステータス (`self.screenshot_status_label`, `self.recording_status_label`) を適切に更新し、「待機中」などの文言でユーザーに実行されていないことを伝える。

4. **停止処理の整合性確認**
   - `stop_all_tasks` など停止関連メソッドがチェックボックス状態に左右されず安全に動作するか確認する。開始しなかった処理に対して停止処理が呼ばれてもエラーにならないよう既存のガード (フラグ判定) が機能していることをテストで確認する。

5. **テスト計画**
   - GUI 上で以下のシナリオを手動テストする:
     1. 両チェックがオンの状態で通常通り開始できること。
     2. 録画のみオフで開始した場合にスクリーンショットのみ動作すること。
     3. スクリーンショットのみオフで開始した場合に録画のみ動作すること。
     4. 両方オフで開始した場合に警告が表示され処理が始まらないこと。
     5. 実行中にチェックを切り替えても UI が矛盾しないこと (開始ボタンが適切に制御されること)。

6. **ログ出力の更新**
   - 重要な分岐 (警告を出した、録画をスキップした、スクリーンショットをスキップした) で `logger.info` / `logger.warning` を追記し、後から挙動を追跡できるようにする。

## 補足
- 要件に合わせて `prepare_save_folder()` を両処理共通で呼ぶ必要があるか再検討する。両方オフの場合は呼び出さずに return する。
- UI 上で録画先ウィンドウが選択されていない場合の扱い (録画オンだがウィンドウ未選択) についても現状仕様を確認し、必要なら追加のメッセージを検討する。
